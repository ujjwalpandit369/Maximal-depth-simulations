State Space of a 1D Cellular Automaton

An interactive explorer for the state space of elementary cellular automata.

Plain-Language Overview

Imagine a row of lights, where each light can be either on or off. Now, imagine a simple set of rules that determines whether a light will be on or off in the next moment, based only on its own state and the state of its immediate left and right neighbors. This is a Cellular Automaton. Even with the simplest rules, these systems can produce patterns of astonishing complexity. Some rules create simple, ordered patterns, while others, like the famous "Rule 30," generate chaos that seems truly random. This simulation lets you enter a rule number (from 0 to 255), set an initial row of cells, and watch the pattern unfold, revealing a glimpse into the vast and beautiful "state space" of possible computations.

Beginner's Guide

1. What is a Cellular Automaton?

At its heart, a cellular automaton (CA) is a very simple "universe" with three key ingredients:

  1. Cells: A grid of cells. In our case, it's just a single 1D row of cells.
  2. States: Each cell can be in a finite number of states. Here, there are only two: "on" (black) or "off" (white).
  3. Rules: A set of rules that determines a cell's state in the next time step. The new state depends only on the cell's current state and the states of its neighbors.

In this simulation, we are looking at Elementary Cellular Automata. "Elementary" means that the rule for a cell only looks at its immediate left neighbor, itself, and its immediate right neighbor—a trio of three cells.

2. Understanding the Rule Number

How can a single number from 0 to 255 define an entire rule set? It's a clever binary trick developed by Stephen Wolfram.

There are exactly 8 possible patterns for a 3-cell neighborhood (where 1 is 'on' and 0 is 'off'):

111, 110, 101, 100, 011, 010, 001, 000

A rule simply has to specify what the center cell should become for each of these 8 cases. This gives us 8 "on" or "off" outputs. For example, for Rule 30:

Current Neighborhood111110101100011010001000
New State for Center Cell00011110

The sequence of outputs is 00011110. If you convert this binary number to decimal, you get 30. That's it! Every number from 0 to 255 corresponds to a unique 8-bit binary number, which defines one of the 256 possible elementary rules. The visualization in the controls area shows you this exact mapping for the rule you select.

3. Exploring Different Rules

The magic happens when you try different rules. Start with a "Single 'On' Cell" and press "Play" or "Step".

  • Rule 90: Produces a beautiful, perfectly nested, self-similar pattern called the Sierpinski triangle. This is an example of ordered complexity.
  • Rule 30: Produces a pattern that appears completely random and chaotic on its left side. This rule is so good at generating randomness that it's been used in software for generating random numbers.
  • Rule 110: Looks like a chaotic mess of interacting particles or waves. It was proven that Rule 110 is "Turing complete," meaning it can, in principle, compute anything a universal computer can. This simple rule contains the power of universal computation!
  • Rule 4, 108, etc.: Many rules quickly die out or produce simple, repetitive block patterns.

By exploring these rules, you are exploring the "state space" of possible computations. You're seeing how the simplest possible ingredients—local rules acting on binary states—can give rise to the entire spectrum of behavior, from order to chaos to universal computation.

FAQ & Troubleshooting

1. What do the black and white squares mean?
They represent the two possible states of a cell. In our simulation, black is "on" (state 1) and white is "off" (state 0).
2. What happens at the edges of the row?
The simulation uses "wrapped" boundary conditions. This means the rightmost cell's right neighbor is the leftmost cell, and the leftmost cell's left neighbor is the rightmost cell. The row is treated like a circle.
3. Why does the simulation stop?
The simulation stops when the pattern reaches the bottom of the canvas. You can press "Reset" to clear it and start over, perhaps with a different rule or initial condition.
4. What does the rule visualization in the controls mean?
It's a direct visual representation of the rule table (like the one for Rule 30 in the guide). It shows each of the 8 possible 3-cell neighborhoods on the top row, and the resulting state for the center cell on the bottom row. It's the "code" the automaton is running.
5. Some rules produce very boring patterns. Is that normal?
Yes, absolutely. Most of the 256 elementary rules produce simple, repetitive, or quickly vanishing patterns. The emergence of profound complexity from rules like 30, 90, and 110 is what makes them so special and interesting to study.
