An interactive tool for exploring the state space of 1D elementary cellular automata.

Estimated runtime: Continuous Recommended device: Desktop

Plain-Language Overview

Imagine a row of lights where each can be on or off. Now, imagine a simple rule that decides a light's next state based on its own state and its immediate neighbors. This is a Cellular Automaton. From the simplest rules, astonishing complexity can emerge. Some rules create simple, ordered patterns, while others, like the famous "Rule 30," generate chaos. This simulation lets you enter a rule number (0-255), set an initial state, and watch the pattern unfold, revealing a glimpse into the vast "state space" of possible computations.

Beginner's Guide

1. The Three Ingredients

A cellular automaton (CA) is a simple "universe" with three parts:

  1. Cells: A grid of cells. Here, it's a 1D row.
  2. States: Each cell has a state. Here, it's "on" (black) or "off" (white).
  3. Rules: A rule determines a cell's next state based on its current state and its neighbors' states.

This simulation explores Elementary Cellular Automata, where the rule for a cell only looks at its immediate left neighbor, itself, and its right neighbor.

2. How the Rule Number Works

A single number (0-255) defines the entire rule set. There are 8 possible patterns for a 3-cell neighborhood (where 1=on, 0=off): 111, 110, 101, 100, 011, 010, 001, 000. A rule specifies the center cell's next state for each case. For Rule 30, the outputs are 0,0,0,1,1,1,1,0. This binary number, 00011110, is 30 in decimal. The "Rule Visualization" shows this exact mapping.

3. Exploring Different Rules

The magic happens when you try different rules. Click a preset or enter a number and press Reset.

  • Rule 90: Creates a perfectly nested, self-similar pattern (the Sierpinski triangle). An example of order.
  • Rule 30: Creates a chaotic pattern that appears random on its left side.
  • Rule 110: Looks like a mess of interacting particles. It's proven to be "Turing complete," meaning it can compute anything a universal computer can.
  • Rule 184: A surprisingly accurate model of traffic flow, where black cells are cars.

FAQ & Troubleshooting

What happens at the edges?
The simulation uses "wrapped" boundary conditions. The rightmost cell's right neighbor is the leftmost cell, and vice-versa, like a circle.
Why does the simulation stop?
It stops when the pattern reaches the bottom of the canvas. Press "Reset" to start over.
